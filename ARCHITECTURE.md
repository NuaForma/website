# Website architecture and release coordination

- This buildless static repository owns `site/`, public kits and website packaging/static QA. It does not host generation, implement product APIs or duplicate product technical guides.
- `develop` is the default working branch. Main is published content, promoted through PRs after the matching product artifacts are available. Urgent signed administrator corrections may go directly to main; synchronize them back to develop. Separate rulesets keep signatures and no-force-push/no-deletion requirements non-bypassable while permitting the narrow review/check exception on main. Pages still depends on successful checks.
- Preserve nuaforma.dev, its www behavior, existing relative paths and downloads. Migration changes repository ownership, not URL layout or example bytes. The current Pages artifact remains the contents of `site/`, never the repository root.
- Product runtime policy is authoritative. The website keeps an immutable-release checksum snapshot of profile inputs solely for packaging and consistency checks. Only explicitly reviewed product releases may update it; private fonts/resources/extensions never enter kits or inventories.
- Production and Playground kits stay separate for native AMD64/ARM64. Playground remains development-only and may log document contents/field values. Retain warnings and isolation without adding a second generator or default network-placement policy.
- Every release delivery assesses website/docs/download/Playground impact. Prepare future site changes on develop, verify exact released versions/digests, repackage all affected kits, promote to main, then verify HTTPS and live hashes. Publishing a product version does not automatically merge website work.
- Preserve original history/signatures without rewrite; the first website-only commit descends from product migration source `00e363fb3760a79c19c1e046bd42e2dcb48a62f5`. The current tree excludes engine/server code and product release workflows.
