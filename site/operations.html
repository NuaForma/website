DEPLOY AND OPERATE

Your fonts.
Your processing policy.

Configure trusted instance settings separately from document requests. Keep isolation, resource limits and the distinction between production and development intact.

Prepared for 0.2.0-alpha.2; these additions are not available in the currently published alpha.1 images. Use the version-matched deployment kits after the release is available.

Fonts: preserve, supply or embed

Default DOCX output preserves template font references. For custom fonts, mount a readable, flat directory of standalone TTF/OTF faces at /opt/nuaforma/custom-fonts using the kit's custom-fonts directory, then restart. GET /api/v1/capabilities lists the provider's available bundled/mounted fonts. Private request uploads are not exposed in that catalog.

To embed the fonts actually used by a supported DOCX document, select DOCX output with these options inside your complete request envelope:

DOCX output selection
"output": {
  "format": "docx",
  "options": {
    "fontMode": "embed",
    "fontSelection": "used"
  }
}

This is not restricted to Arial-like fonts: supported effective families and regular/bold/italic/boldItalic faces are resolved after template expansion. Unused catalog fonts are not embedded. Explicit declarations take precedence over mounted fonts, then bundled fonts; already embedded faces are retained. Missing faces, ambiguous identities, unsupported font-resolution constructs and prohibited embedding fail explicitly, without silent substitution. Font availability is not a guarantee of glyph coverage or support for every Word feature.

For request-private fonts, declare each fonts entry with its family, face and logical resource ID, then attach its bytes as multipart resource.<id>. The Playground can prepare these declarations and uploads, or select automatic used-font embedding when supported. Fonts are never installed globally. Follow the font and embedding reference for the exact supported profile, bounds and permissions.

One malformed mounted font no longer disables every otherwise usable font. Rejected files are excluded and logged safely; a request that requires an unavailable or conflicting face still fails. Fix the file and restart to refresh the immutable catalog. Existing valid embedded fonts and explicit request resources retain their documented precedence.

Diagnose templates without exposing production data

Production API errors remain restricted. Explicit NUAFORMA_MODE=development enables fixed application-owned rejection explanations and remediation for recognized conditions. Internal logging uses request IDs for correlation; development logging may contain document content and field values. It is not safe to enable casually with confidential data.

The separate Playground container enables development mode and shows conspicuous warnings. It is not the production image. Configure your own authentication/TLS gateway and log access controls; arbitrary extension errors are not forwarded as public explanations. See the logging and privacy guide.

Bounded PDF concurrency

NUAFORMA_PDF_PARALLELISM defaults to 1 and accepts 1 through 8. This operator setting controls concurrent PDF runtime processes per provider instance; it is not a per-request option or the HTTP admission limit. Requests may wait for slots. Increasing it requires CPU, memory, process-limit and temporary-storage headroom; eight is not a recommended default. Read the short processing trials and their limitations and size against your own documents.

PDF/A validation stays on by default

An absent NUAFORMA_PDFA_VALIDATION or exact true enables per-document veraPDF conformance validation. Only exact false disables that stage; empty, whitespace, alternate-case and unknown values fail startup. This trusted instance setting cannot be changed by request JSON or a template.

With validation disabled, PDF/A conformance is not checked by NuaForma. Output is generated using the requested profile, and the operator owns downstream conformance checking. Capabilities report the active policy separately from available formats; the Playground shows a warning, not a request-level switch.

PDFBox structural, active-content and embedded-font checks remain mandatory, as do profile restrictions, private files, network denial, cancellation and processing limits. Disabling veraPDF does not disable security or permit unsupported PDF/A-1b transparency. Standard PDF and DOCX retain their behavior. Default deployment examples keep validation enabled.

Optional Compose instance settings
environment:
  # Keep the other environment entries from the complete kit.
  NUAFORMA_PDFA_VALIDATION: "true"
  NUAFORMA_PDF_PARALLELISM: "1"
