SHORT PROCESSING TRIALS · 16 OCTOBER 2026

Measured examples.
Not a capacity promise.

How much work can NuaForma handle? These small, bounded experiments give an indication for one synthetic business document. They are not large-scale load tests over a long period, production sizing recommendations or hourly throughput guarantees.

Test baseline: a private Linux AMD64 development build from source c5d8774, including the fixes in issue #91. This is not a performance claim for an unchanged published alpha image, ARM64 or arbitrary Word documents.

What was processed?

The completed REST trials used the public synthetic Word example, nested JSON data and two-page PDFs. Each response was independently parsed and checked for its own unique reference, without another request's reference. PDFBox, veraPDF for PDF/A, resource limits and isolated, network-denied conversion remained enabled.

The returned documents were 582 DOCX, 146 standard PDF and 144 PDF/A-3b files. The 32 503 SERVER_BUSY responses were deliberate admission-limit rejections during bursts against a four-request limit, not successful documents. Both completed groups had healthy observations throughout, with no OOM, restart or process-limit events. An earlier pre-fix trial did encounter an availability failure; it led to issue #91 and is not counted as a successful trial here.

Concurrency is not throughput.

Sixteen concurrent standard-PDF requests and sixteen concurrent PDF/A requests succeeded with two PDF process slots and a sixteen-request admission limit. That does not mean sixteen renderers were running simultaneously: requests can wait for available processing slots.

These calculated rates come from individual short stages, not a full minute or hour of sustained processing. Three slots did not outperform two in this trial. Four left very little process-limit headroom, so six or eight were not tested; the instance was returned to two slots for margin. The sixteen-client test used two slots, not four. Peak memory across the larger-budget trials was about 1.22 GiB.

What does veraPDF cost?

A separate paired pipeline experiment used the same populated DOCX and unmodified sandbox, font lookup, PDF/A-3b conversion and PDFBox checks. Four batches of twelve jobs alternated with veraPDF, without, without, then with it, using two workers and the same 5 CPU / 8 GiB budget.

Skipping veraPDF produced approximately 1.96 times the throughput in this paired experiment, with 49.1% less elapsed time. All 48 jobs passed PDFBox; only the 24 full-validation jobs were checked for PDF/A conformance. Normal API validation was never disabled and a final ordinary PDF/A API request also passed. Benchmark-only files without conformance checks were not served as validated PDF/A.

This harness excluded HTTP and template processing and added a container-execution call per operation. Its absolute rates cannot be compared directly with the REST rates above or used as a multiplier for other workloads. The default-on operator validation setting from issue #93 is available from 0.2.0-alpha.2; the figures above retain their original source baseline and are not new alpha.2 measurements. See the operations guide for the default-on policy and its boundaries.

Test your own workload.

Most REST stages issued requests for roughly 30–60 seconds, with finite request counts; accepted requests were allowed to finish afterwards. Host budgets were changed between groups, and other workload state was not identical across all groups. The PostgreSQL replica was temporarily stopped for the larger-budget REST group, but running during the smaller-budget and paired A/B trials. These are not controlled CPU-only comparisons or statistically established scaling curves.

Use representative documents and longer repeated runs to establish throughput, tail latency, memory/process headroom and failure recovery on your infrastructure. Document size, page count, fonts, tables, images, PDF/A checks and available CPU all matter. Do not multiply these short rates into an advertised hourly capacity or treat them as evidence of production readiness.
