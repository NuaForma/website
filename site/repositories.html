CHOOSE YOUR RELEASE CHANNEL

Stable releases.
Development previews.

NuaForma and Image Comparison use Maven Central for stable libraries and public Nexus repositories for new development versions. Add only the repository for the versions you intend to use.

Existing downloads keep working. NuaForma 0.3.0-alpha.4 and earlier published alphas remain on Maven Central, as does Image Comparison 5.0.0. These changes do not move or replace published artifacts. Keep the versions in the current getting-started examples to try those releases.

Stable

X.Y.Z

Use Maven Central. Maven already includes Central; Gradle builds declare mavenCentral(). Published versions are fixed.

Prerelease

X.Y.Z-alpha.N, beta or RC

New development previews use Nexus prereleases. Each version is fixed once published. In Maven these count as releases, so enable releases for this repository.

Snapshot

X.Y.Z-SNAPSHOT

Use Nexus snapshots. The same dependency version can resolve to a newer timestamped build later. Choose an immutable release when you need repeatable dependency selection.

These are version formats, not a list of available artifacts. Select an actually published version. Alpha and snapshot builds are intended for evaluation; they are not stable API promises. Repository selection affects libraries, not the existing container download kits.

Use a new alpha, beta or RC

Add this repository alongside your existing configuration, then select the desired published development version in your dependencies. Keep all NuaForma dependencies aligned. Maven's standard Central configuration and Gradle's mavenCentral() remain available for existing releases and third-party libraries.

build.gradle.kts · prereleases
repositories {
    mavenCentral()
    maven {
        name = "nuaforma-prereleases"
        url = uri("https://repo.nuaforma.dev/repository/nuaforma-prereleases/")
        content { includeGroup("dev.nuaforma") }
        mavenContent { releasesOnly() }
    }
}
pom.xml · prereleases
<repositories>
  <repository>
    <id>nuaforma-prereleases</id>
    <url>https://repo.nuaforma.dev/repository/nuaforma-prereleases/</url>
    <releases><enabled>true</enabled></releases>
    <snapshots><enabled>false</enabled></snapshots>
  </repository>
</repositories>

Use a snapshot deliberately

Add the separate snapshot repository and use the published -SNAPSHOT dependency version. Maven and Gradle resolve its timestamp/build-number metadata; do not invent a timestamped filename or use a snapshot version in the prerelease repository.

build.gradle.kts · snapshots
repositories {
    mavenCentral()
    maven {
        name = "nuaforma-snapshots"
        url = uri("https://repo.nuaforma.dev/repository/nuaforma-snapshots/")
        content { includeGroup("dev.nuaforma") }
        mavenContent { snapshotsOnly() }
    }
}
pom.xml · snapshots
<repositories>
  <repository>
    <id>nuaforma-snapshots</id>
    <url>https://repo.nuaforma.dev/repository/nuaforma-snapshots/</url>
    <releases><enabled>false</enabled></releases>
    <snapshots><enabled>true</enabled></snapshots>
  </repository>
</repositories>

Build tools may cache changing versions. When deliberately checking a newer snapshot generation, use mvn -U verify or ./gradlew build --refresh-dependencies. A later build may resolve different snapshot bytes even when the declared version stays the same.

Anonymous downloads. Controlled publishing.

No repository username, password or private token is needed to use these libraries. Publishing requires maintainer authentication. Never put publishing credentials in a consumer example or a public project.

Maintainers publish snapshots manually from a signed, green develop commit using Publish snapshot to Nexus (manual). There is no automatic publication on a push. Immutable releases keep their protected approval process; only stable releases go to Central. The repository guides own the detailed checks and recovery instructions.
